# Your HAL publications in a GitHub README

This guide is for researchers who want their publication list on a GitHub profile, a project README or any page written in Markdown. You don't need any JavaScript.

The list is an SVG image generated by `https://hal-search.vercel.app` from the [HAL](https://hal.science/) open archive. It updates by itself when you deposit new work in HAL.

[![Publications of Jey Puget Gil on HAL](https://hal-search.vercel.app/svg?idHal=jpugetgil&rows=3)](https://cv.hal.science/jpugetgil)

> The **[configurator](https://jpugetgil.github.io/hal-search/)** builds the snippet for you, with a live preview.

## 1. Find your HAL author identifier (idHal)

Your idHal is the last part of your HAL CV address: `https://cv.hal.science/`**`jdupont`**.

- Sign in to [hal.science](https://hal.science/) and open the IdHAL page of your account space (*My space → My IdHAL*, *Mon espace → Mon IdHAL* in French). If you don't have one yet, create it there.
- Check it: `https://cv.hal.science/YOUR_IDHAL` must open your CV.

No idHal? You can use one of these instead:

| Instead of `idHal=…` | When |
|---|---|
| `orcid=0000-0002-1825-0097` | Your HAL deposits are linked to your ORCID iD (the `https://orcid.org/…` form works too) |
| `q=authFullName_s:%22Jane%20Doe%22` | Raw Solr query on the exact author name as written in HAL (`%22` = `"`, `%20` = space). Namesakes will show up too |

A publication only appears if HAL links it to you. If some are missing from your HAL CV, link them to your idHal in HAL (or ask your HAL support team) and they will appear in the image too.

## 2. Build the image URL

Start with:

```
https://hal-search.vercel.app/svg?idHal=YOUR_IDHAL
```

Open it in your browser: you should see your 10 most recent publications. Then add options with `&name=value`:

| Add | Effect |
|---|---|
| `&rows=5` | Number of publications (1–20, default 10) |
| `&lvl=0` | Compact: one citation line per publication |
| `&lvl=2` | Adds the Open Access badge, keywords and domains (`lvl=3` also adds the abstract, which makes a tall image) |
| `&docTypes=ART,COMM` | Only some document types: `ART` journal articles, `COMM` conference papers, `COUV` book chapters, `OUV` books, `THESE` thesis, `HDR`, `POSTER`, `REPORT`, `SOFTWARE`, `UNDEFINED` preprints… |
| `&yearFrom=2020` / `&yearTo=2024` | Year range (inclusive) |
| `&oa=1` | Open access publications only |
| `&groupBy=year` | Year headings (`groupBy=docType`: one heading per document type) |
| `&highlight=YOUR_IDHAL` | Your name in bold in the author lists. Prefer your idHal: the list is comma-separated, so a full name only works without a comma (`First%20Last`) |
| `&maxAuthors=5` | Authors shown before "et al." (`0` = all, default 10) |
| `&sort=date-asc` | Oldest first (`relevance` is also available; the default is newest first) |
| `&title=Recent%20publications` | Header title (`%20` = space, max 80 characters) |
| `&theme=dark` | Dark colors (`light` by default, `auto` follows the viewer's OS) |
| `&main=%23c8102e` | Accent color (`%23` = `#`). Also `bg` (card background) and `text` |
| `&credit=0` | Hides the small "hal-search" credit |

Example:

```
https://hal-search.vercel.app/svg?idHal=jpugetgil&rows=5&docTypes=ART,COMM&groupBy=year&highlight=jpugetgil
```

All parameters are listed in the [README](../README.md#url-parameters).

## 3. Paste it into your README

Your **profile README** is the `README.md` of the repository named after your GitHub username (`github.com/USERNAME/USERNAME`).

```md
## Publications

[![My publications on HAL](https://hal-search.vercel.app/svg?idHal=YOUR_IDHAL&rows=5)](https://cv.hal.science/YOUR_IDHAL)
```

GitHub displays images through its image proxy (camo), inside an `<img>`: links inside the image **can't be clicked**. The outer link makes the whole image open your HAL CV.
Write a meaningful alternative text between `[!` and `]` for screen-reader users.

## 4. Follow GitHub's light and dark theme

`theme=auto` follows the viewer's **operating system**, not the theme chosen in GitHub's settings. To follow GitHub's theme, give GitHub two images with a `<picture>` element:

```html
<a href="https://cv.hal.science/YOUR_IDHAL">
  <picture>
    <source media="(prefers-color-scheme: dark)" srcset="https://hal-search.vercel.app/svg?idHal=YOUR_IDHAL&amp;rows=5&amp;theme=dark">
    <img src="https://hal-search.vercel.app/svg?idHal=YOUR_IDHAL&amp;rows=5&amp;theme=light" alt="My publications on HAL">
  </picture>
</a>
```

In HTML, `&` is written `&amp;` (a plain `&` also works on GitHub). Leave an empty line before and after the HTML block in your Markdown.
This is the output of `buildMarkdownSnippet({ svgBase: 'https://hal-search.vercel.app', darkMode: true, … })`, and of the configurator's "Follow the GitHub light/dark theme" option.

## 5. Troubleshooting

**My new publication doesn't show up.**
Images are cached for 1 hour by the service, and GitHub's image proxy can keep them longer. HAL itself may need a moment to index a new deposit.
To force a refresh, change the URL, for example by adding an unused parameter such as `&v=2` (unknown parameters are ignored).

**The image shows an error message.** Errors are rendered as an image, so your README never shows a broken image:

| Message | What to do |
|---|---|
| *Missing query: add idHal, orcid, collection, structId, search or q to the image URL.* | The URL has no (valid) criterion. Check the parameter name (`idHal`, case-sensitive) and the value. A `search=` made only of symbols such as `***` doesn't count |
| *HAL rejected this query: check the URL parameters.* | Usually a raw `q=` query with a Solr syntax error |
| *HAL did not answer in time. Please try again later.* | HAL took more than 4 seconds. Error images are only cached for 60 seconds, so it fixes itself |
| *Could not load publications from HAL. Please try again later.* | HAL is unavailable, try again later |

**The list is empty ("No results found.").** Open `https://cv.hal.science/YOUR_IDHAL`. If your CV is empty too, your publications aren't linked to your idHal yet (see step 1). Also check your filters (`docTypes`, `yearFrom`, `oa`).

**Someone else's publications appear.** You probably used `search=` (free text) or a name query. Use `idHal=` or `orcid=`.

**The image is too long.** Lower `rows` (at most 20 publications per image), use `lvl=0`, or filter with `yearFrom=`. The outer link takes readers to your full list on HAL.

**My colors are ignored.** Encode `#` as `%23` (`main=%23c8102e`). Accepted formats: hex, `rgb()`, `hsl()` and named colors.

**The fonts look different from the preview.** The image uses the viewer's system fonts (an `<img>` can't load web fonts). Long titles are cut with "…" to stay inside the cards.

**I want it in French.** The image service has no translation parameter. `title=` changes the header, but the other labels stay in English. For a fully translated list on your own website, use the [web component](lab-website.md#6-french-labels) instead.

## Other Markdown hosts

The same URLs work wherever Markdown or HTML images are allowed (GitLab, Codeberg, static site generators, wikis).
On a website where you can add a `<script>`, the [web component](lab-website.md) gives clickable links, pagination and translations.
